## 这个月的具体账

- **AI 工具**：2 月初开始轮着用，到 05-02 正好 90 天。第四个装了两天没过公司代理，弃了，所以横评只写了三个。退掉的是 $19/月 和 $10/月 两个，留下的那个按团队版走、不占我自己的预算。退订页要填「离开原因」，我勾了「太贵」，其实不是钱的事——它每回都执意把 `@Transactional` 改成 `@Transactional(rollbackFor = Exception.class)`，我纠正了六次，第六次关掉了窗口。
- **RAG**：第一版 05-03 上线，四天累计 1240 万 input token，折三十来块美元。钱不多，荒唐的是量。改成按 Markdown 标题切 chunk（512 token、重叠 64）、pgvector 检索 top-5 之后，单次均值从 1.5 万降到 1800 上下，日均 input 从 470 万落到 60 万左右。embedding 存的是 pgvector 一张表，chunk 正文、标题路径、书 id 三列，检索时先按书 id 过滤再算距离。top-5 里第 4、5 条经常是无关章节，这本该是 rerank 干的活，月底没腾出手。
- **Spring Boot 升级**：升的是在线书店那个服务，跟四月写虚拟线程的订单查询服务不是一回事（那边本来就 3.2.5）。`javax.*` → `jakarta.*` 的批量替换撞了 214 个文件，第一轮挂了 31 个测试；剩下 16 个里，13 个是 `WebSecurityConfigurerAdapter` 没了、`HttpSecurity` 写法变了，3 个是 Hibernate 6 改了 sequence 命名策略、断言里写死的 ID 对不上。47 个测试从 05-13 挂到 05-15。批量替换还误伤了一处字符串常量里的 `javax.annotation`，测试里反序列化失败才炸出来，`git diff` 翻了两遍才找到那行。
- **CI 时长**：升级后全量构建从 4 分 12 秒涨到 6 分 48 秒。给 Maven 开了 `-T 1C` 并行编译压回 4 分 35 秒，测试分片没敢动，那几个有状态的集成测试会互相踩。
- **库存**：05-18 对账查出一个 SKU 被扣了两次，是消费者重启后重复消费。事务和数据库唯一约束最后都上了，细节在下面。
- **站点**：GitHub Actions 自动部署搭起来了，四月那句「本地 `hexo generate` 再手动拷，太蠢了」可以划掉。`hexo generate` 冷启动还是 1.9 秒，push 到线上整条 workflow 一分四十秒左右。

## 踩坑记录

**一、整本书塞进 prompt。** 第一版图省事，把书按纯文本读出来直接拼进 system prompt，问答确实能跑，就是没人去看账单。我在 `tools/` 下写了个汇总脚本，把导出的 usage csv 按天摊开：

```python
#!/usr/bin/env python3
"""把 usage 导出的 csv 按天摊开，算单次问答的 input token 均值。
用法: python3 tools/token_bill.py data/usage-2026-05.csv
"""
import csv
import sys
from collections import defaultdict

bill = defaultdict(lambda: {"input": 0, "calls": 0})
with open(sys.argv[1], newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        day = row["date"][:10]
        bill[day]["input"] += int(row["input_tokens"])
        bill[day]["calls"] += 1

for day in sorted(bill):
    b = bill[day]
    avg = b["input"] // max(b["calls"], 1)
    flag = "  <-- 超阈值" if avg > 8000 else ""
    print(f"{day}  input={b['input']:>9}  calls={b['calls']:>4}  单次均值={avg:>6}{flag}")
```

跑出来头两行是这样：

```text
2026-05-03  input=  1184022  calls=  78  单次均值=15179  <-- 超阈值
2026-05-06  input=  4701833  calls= 312  单次均值=15069  <-- 超阈值
```

阈值 8000 是我拍的，够用。切 chunk 也不顺：最早按固定 512 字符硬切，表格和代码块被拦腰截断，问「配置怎么写」召回的全是半截 YAML。换成按标题层级切才像样。rerank 到月底没接上。

**二、47 个测试和那个漏掉的 `--add-opens`。** 升级后有个做反射的老库在 JDK 21 上抛这个：

```text
java.lang.reflect.InaccessibleObjectException:
Unable to make protected final java.lang.Class
java.lang.ClassLoader.defineClass(...) accessible:
module java.base does not "opens java.lang" to unnamed module @6d06d69c
```

我在 `pom.xml` 的 surefire 里补了参数，CI 和生产启动脚本也各加了一份：

```xml
<!-- pom.xml / maven-surefire-plugin 3.2.5 -->
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-surefire-plugin</artifactId>
  <version>3.2.5</version>
  <configuration>
    <argLine>
      --add-opens java.base/java.lang=ALL-UNNAMED
      --add-opens java.base/java.util=ALL-UNNAMED
      -Xmx1024m
    </argLine>
  </configuration>
</plugin>
```

偏偏预发那台用的是另一份老 `JAVA_OPTS`，没同步。05-20 那次发布跑到预发的集成测试直接抛异常，发布单回滚，第二天补齐才过。三份环境三份配置，纯属自找的。

**三、重复扣库存。** 一开始以为把生产者的 `enable.idempotence` 打开就完事，后来才分清：幂等只管「重试别写重」，管不了「读一条消息 → 扣库 → 提交 offset」这三步的原子性。最后两条都上了——Kafka 事务（`sendOffsetsToTransaction` + `read_committed`）加一张按 `order_id + sku_id` 建唯一约束的流水表兜底。对账用的那条 SQL：

```sql
-- 对账：同一 order_id + sku_id 出现在两条扣减流水里
SELECT order_id, sku_id, COUNT(*) AS cnt, SUM(delta) AS total
FROM stock_ledger
WHERE created_at >= '2026-05-18'
GROUP BY order_id, sku_id
HAVING COUNT(*) > 1;
```

输出就一行：`884213 | B-0917 | 2 | -2`。同一笔订单扣了两次，账面平不了才被捞出来。

## 顺手写的搜索索引

给博客加了站内搜索，`hexo generate` 之后多跑一步生成 `public/search.json`。四月那个扫图片引用的脚本还躺在 `tools/` 里，这次一起收拾了：

```python
#!/usr/bin/env python3
"""从 _posts 生成 public/search.json；hexo generate 之后跑。
剥掉 front-matter、围栏代码和图片，避免索引塞满类名和路径。
"""
import json
import re
from pathlib import Path

posts = Path("source/_posts")
fm = re.compile(r"^---\n.*?\n---\n", re.S)
code = re.compile(r"```.*?```", re.S)
img = re.compile(r"!\[[^\]]*\]\([^)]*\)")
tag = re.compile(r"<[^>]+>")

def clean(md):
    body = fm.sub("", md, count=1)
    body = code.sub("", body)
    body = img.sub("", body)
    body = tag.sub("", body)
    return re.sub(r"\s+", " ", body).strip()

index = []
for p in sorted(posts.glob("*.md")):
    text = p.read_text(encoding="utf-8")
    title = re.search(r'^title:\s*"(.+?)"', text, re.M)
    y, m, d = p.name[:10].split("-")
    index.append({
        "title": title.group(1) if title else p.stem,
        "date": p.name[:10],
        "path": f"/{y}/{m}/{d}/{p.stem[11:]}/",
        "text": clean(text)[:2000],
    })

out = Path("public/search.json")
out.write_text(json.dumps(index, ensure_ascii=False, separators=(",", ":")), encoding="utf-8")
print(f"{len(index)} 篇, {out.stat().st_size} 字节")
```

输出 `17 篇, 68412 字节`。索引里剥掉了围栏代码和图片，不然搜「虚拟线程」会命中一堆类名。前端就是一个 input 加一段 `fetch`，输入时把 68 KB 的 json 全拉下来在内存里过滤，17 篇的量级犯不上引第三方搜索库。

> 顺带一提：这份索引没分词，输入「虚拟线程」能命中，输入「虚拟」就不行，因为只是子串匹配。试过接一个 wasm 版结巴，包体 1.4 MB，比整份索引还大二十倍，先放下了。
