## 线程池与多线程取舍

## 产生原因

以前遇到的文件下载做法是重新写一个xxxExport

但是遇到一个更好的办法，直接使用我们select中的Page即可

具体方法如下

```java
//写入headers
String[] headers = {"","",""}; 
//调用select中的函数，拿到Page
Page page = selectxxx(pageNo,PageSize);
//拿到Page中的总页数
Page page2 = selectxxx(1,(int)page.getTotal());
//执行excelDownload
excelDownLoad(response,headers,page2);
```

因为循环内部出现查询和判断，执行效率极其慢，查一页是10s，查146条基本上是∞，所以果断采用了多线程进行提速，因为执行的数据不是相互依赖的数据，所以可以选择普通的多线程方法。

> 前后踩得坑
>
> - 坑一：自己参照写了一个List来承接数据，然后进行处理
>
>   处理速度没有任何提升，甚至还需要自己多次修改。
> - 坑二：使用线程池来加速处理
>
>   因为迭代器自身是一个类似于悲观锁的处理机制，在线程无法处理时就跳过处理，导致数据无法拿到
> - 坑三：可能会导致OOM
>
>   这个暂时没法解决，为了速度牺牲内存

```java
public void excelDownLoad(HttpServletResponse response, String[] headers, Page page) throws IOException {
        // 声明一个工作薄
        XSSFWorkbook workbook = new XSSFWorkbook();
        // 生成一个表格
        XSSFSheet sheet = workbook.createSheet();
        // 设置表格默认列宽度为15个字节
        for (int i = 0; i < headers.length; i++) {
            int colWidth = sheet.getColumnWidth(i) * 2;
            if (colWidth < 255 * 256) {
                sheet.setColumnWidth(i, colWidth < 3000 ? 3000 : colWidth);
            } else {
                sheet.setColumnWidth(i, 6000);
            }
        }

        XSSFRow row = sheet.createRow(0);
        for (short i = 0; i < headers.length; i++) {
            XSSFCell cell = row.createCell(i);
            XSSFRichTextString text = new XSSFRichTextString(headers[i]);
            cell.setCellValue(text);
        }

        //遍历集合数据，产生数据行
        Iterator it = page.getRecords().iterator();
        int index = 0;
        while (it.hasNext()) {
            index++;
            row = sheet.createRow(index);
            Map<String, Object> map = JSONObject.parseObject(JSONObject.toJSONString(it.next()), Map.class);
            ImplProjectExcelVo objectValue = JSONObject.parseObject(JSONObject.toJSONString(map), ImplProjectExcelVo.class);
            //利用反射，根据javabean属性的先后顺序，动态调用getXxx()方法得到属性值
            Field[] fields = objectValue.getClass().getDeclaredFields();
            // 这里遍历fields 每个属性
            for (short i = 0; i < fields.length; i++) {
                XSSFCell cell = row.createCell(i);
                Field field = fields[i];
                String fieldName = field.getName();
                String getMethodName = "get" + fieldName.substring(0, 1).toUpperCase() + fieldName.substring(1);
                // 提取getName() 这样方法
                try {
                    Class tCls = objectValue.getClass();
                    Method getMethod = tCls.getMethod(getMethodName,
                            new Class[]{});
                    Object value = getMethod.invoke(objectValue, new Object[]{});
                    // 通过底层invoke 开启bug拿到值
                    String textValue = null;
                    // 对于日期的值 转为日期 非日期的值当做字符串处理
                    if (value instanceof Date) {
                        Date date = (Date) value;
                        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
                        textValue = sdf.format(date);
                    } else {
                        //其它数据类型都当作字符串简单处理
                        if (value == null) {
                            textValue = "";
                        } else {
                            textValue = value.toString();
                        }
                    }
                    cell.setCellValue(textValue);
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }
        }
        response.setCharacterEncoding("UTF-8");
        // 设置contentType为excel格式
        response.setContentType("application/vnd.ms-excel;charset=utf-8");
        //默认Excel名称
        response.setHeader("Content-disposition", "attachment;filename=" +
                new String("表名".getBytes("utf-8"), "ISO-8859-1") + ".xlsx");
        try {
            response.flushBuffer();
            workbook.write(response.getOutputStream());
        } catch (IOException e) {
            e.printStackTrace();
            throw new IOException("导出Excel出现严重异常，异常信息：" + e.getMessage());
        } finally {
            try {
                workbook.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }
    }
```

## 2026 补记：虚拟线程来了，池没消失

JDK 21 之后，IO 密集的那部分我改成虚拟线程了；CPU 密集和需要控制并发上限的场景仍然用平台线程池，两者不是替代关系：

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.util.concurrent.Executors;
import java.util.concurrent.Semaphore;
import java.util.stream.IntStream;

public class VirtualThreadDemo {
    public static void main(String[] args) {
        HttpClient client = HttpClient.newHttpClient();
        HttpRequest request = HttpRequest.newBuilder(URI.create("https://example.com")).build();
        Semaphore limit = new Semaphore(64);   // 下游扛不住时用它限流，别靠固定大小的池

        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            IntStream.range(0, 100).forEach(i -> executor.submit(() -> {
                limit.acquireUninterruptibly();
                try {
                    return client.send(request, HttpResponse.BodyHandlers.ofString()).body().length();
                } catch (Exception e) {
                    return -1;
                } finally {
                    limit.release();
                }
            }));
        }
    }
}
```

一个值得记下来的坑：虚拟线程在 `synchronized` 块里遇到阻塞 IO 会 pin 住载体线程，JDK 21 不会自动卸载。当年为了线程安全加的一堆 `synchronized`，升级时得挨个看一遍，必要时换成 `ReentrantLock`。
